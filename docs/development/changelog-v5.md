# ASTRA v4.x → v5.22.1 Changelog

Version-change rationale moved out of CLAUDE.md (which is loaded every session) to keep the session context lean. Newest first.

> **v5.22.0 → v5.22.1 change (`/landing-page` execution verification — four defects that reading-based review could not see)**: v5.22.0 shipped after an adversarial `loop-verifier` pass scored 97/100 by *reading* the skill. Actually **executing** its three load-bearing code paths — the ffmpeg loop pipeline, the ego capture heredocs against live Pinterest, and `loop-video.js` in a real browser — found four defects, each of which would have produced a silently broken deliverable. (1) **The `xfade` self-crossfade command aborted every time**: after `trim`+`setpts` the frame-rate metadata reads `1/0`, and `xfade` rejects non-CFR input with `The inputs needs to be a constant frame rate`, writing no output at all — the verifier had checked the offset arithmetic (correct) but could not know ffmpeg's CFR requirement. Fixed by deriving `r_frame_rate` with ffprobe and re-asserting it via `fps=` in both trim chains, plus an explicit duration check; verified to exit 0 and produce exactly D − F seconds. (2) **The documented modal-dismiss sweep deleted Pinterest's feed**: `remove()` over `[data-test-id*="modal"], [role="dialog"]` matched an obfuscated-class ancestor *wrapping the grid*, yielding a pure-white 14 KB capture that the old "is the file non-empty" check would have accepted. Replaced with hide-instead-of-remove, an explicit skip for any node containing the feed, a post-sweep feed-height guard that aborts before capturing, and neutralization of the separate full-viewport `rgba(0,0,0,0.6)` backdrop that was washing every reference dark and biasing palette analysis (capture 1.8 MB → 2.6 MB of true color). (3) **The pin-ID extraction never worked**: `snapshotText()` returned zero `/pin/{id}/` matches on a grid holding 44 pin anchors (it emits an accessibility outline, not hrefs) — replaced with a `js()` DOM query, which returns real hrefs. (4) **The Step 5.B smoke test asserted the impossible on the default backend**: ego agent Task Spaces are hidden tabs with a frozen paint loop (measured `visibilityState: "hidden"`, `requestAnimationFrame` firing **0×/2 s**), so Chromium never decodes media — a perfectly working page reports `readyState 0` / `currentTime 0` / `duration 0` forever with no `video.error` and the mp4 already fetched, while the same page in a visible tab reaches `readyState 4` at `currentTime 2.61`. The old assertion (`currentTime > 0`) would have failed on every run and sent the convergence loop into "fixing" working code. Step 5.B now splits structural assertions (any backend) from playback assertions (visible tab only, escalate to Chrome MCP or `handOffTaskSpace`, otherwise report *unverified* — never failed). The same hidden-tab discovery generalizes beyond this skill, so `docs/development/browser-backend-policy.md` gained **ego operating rule 12** (hidden tab · no media decode · no rAF · a freshly navigated page can stay unpainted for over a minute while every readiness signal lies · in-round `wait()` does not help, only a new round does · blank PNGs are ~14 KB) and a third escalation row for playback/rAF-dependent behavior — this affects `/test-run`, `/user-test`, `/manual-generator`, and `/catalog-generator` equally. `loop-video.js` itself needed **no changes**: in a visible tab every documented claim verified empirically — dual injection with correct attributes, the crossfade caught mid-swap (both videos playing at t = 2.69/0.03, opacities 0.935/0.065), multi-cycle looping, the pause control revealed only after `play()` resolves at 127 × 44 px with working freeze/resume and `aria-pressed`, zero videos injected under `prefers-reduced-motion`, and `hero-mobile.mp4` selected at 390 × 844 with no horizontal overflow; those measured values are now recorded in `video-integration.md` §8 as the expected shape of a passing smoke test. SemVer: patch (documentation/procedure corrections to a shipped release; no new capability).

> **v5.20.0 → v5.21.0 change (ego (lite) promoted to plugin-wide default browser backend)**: user-requested inversion of the v5.20 ordering, plus an expansion of scope from one skill to four. **Detection order is now `ego` (default) → `chrome-mcp` (fallback) → `cmux` (legacy)** — cmux is demoted rather than deleted, so cmux-pane users keep a working path and `references/browser-cmux.md` survives intact. Rationale for making ego the default: its isolated Task Space per agent is the only backend that survives **concurrent Claude Code sessions** without profile `SingletonLock` contention (the failure v5.18 unbundled chrome-devtools to work around), and its inherited login state removes the SSO/2FA dead end on internal test targets. **Scope expansion**: `/user-test`, `/manual-generator`, and `/catalog-generator` previously had no ego path at all (Chrome MCP tool calls were hardcoded into their procedures); all three now resolve a backend and drive ego by default. `/uat-parallel` is deliberately excluded — it drives Playwright as a subprocess with a per-worker `BrowserContext`, so it has no MCP/ego backend to switch. **New SSoT**: `docs/development/browser-backend-policy.md` holds the detection snippet, capability matrix, the three-backend action mapping, the ego operating rules (one heredoc = one round · `cliLog` as the only output channel · seconds-not-milliseconds · `@N` ref expiry · blank-screenshot-on-scroll · handoff-is-a-hard-stop · origin-scoped session clearing · mandatory `completeTaskSpace`), the two escalation cases, the shared deliverable-screenshot recipe, and Task Space naming per skill. Skills reference it instead of restating the order — `/test-run`'s Step 1-A action table was **deleted** in favor of that reference (it was a verbatim duplicate and a drift risk), which also kept SKILL.md inside the 500-line gate. **New reference**: `skills/user-test/references/browser-ego-uat.md` maps UAT's four assertion classes onto ego (CDP collectors installed at session start; `drainEvents()` once per step, which matches the "since the step started" semantics exactly; an explicit DOM probe instead of snapshot-scraping) and states the two places ego cannot verify an assertion — cross-origin `responseStatus` and missing CDP network events — both of which resolve to **FAIL with an unobservable-value note or a `chrome-mcp` re-run, never a PASS**. **Escalation rules** (unchanged in spirit, now centrally stated): performance traces and, where CDP events fall short, console listing escalate to Chrome MCP per-step; the rest of the run stays on the detected backend. **Setup surface**: `/astra-setup` Step 4 lists `ego-browser --version` as an optional macOS prerequisite with the install pointer, its Step 3 labels `chrome-devtools` as the fallback backend, and `scripts/verify-setup.sh` gained a matching optional check. **Deliverable-integrity guard**: because manual/catalog screenshots are published artifacts rather than test evidence, the recipe requires verifying each capture is non-blank and *stating* any document-only fallback in the output — a manual that silently ships without its screenshots was previously reportable as success. **Verified against the installed runtime, not inferred** (ego lite 0.4.5.8 / chromium 150): every helper named in the policy doc exists in the heredoc runtime; `captureScreenshot(absolutePath)` accepts a path, writes the PNG, and returns that path (the upstream skill documents only the no-argument form, so the ASTRA-specific path contract needed proof); `drainEvents()` returns a `{ method, params, sessionId }` CDP array carrying `Runtime.consoleAPICalled` (`params.type`, `params.args[].value`) and `Network.requestWillBeSent` / `Network.responseReceived` (`params.response.url`/`.status`) once the domains are enabled before navigation — which is what makes UAT's console and network assertions implementable on ego at all. That probe also surfaced a caveat absent from every prior document: **login-state inheritance also inherits the profile's extensions**, so a plain page load drained four responses of which three were `chrome-extension://…/contentscript.js`. Every consumer now filters `chrome-extension://` before evaluating `network: no failed requests` / `console: no error`, since otherwise those assertions fail for reasons unrelated to the app under test (a class of false failure that does not exist in Chrome MCP mode with a dedicated profile). SemVer: minor (default-path change; every backend remains reachable, and hosts without `ego-browser` behave exactly as before via the Chrome MCP fallback).

> **v5.19.2 → v5.20.0 change (ego (lite) as `/test-run`'s second browser backend)**: `/test-run` gains a third backend option between the existing two. **ego lite** ([citrolabs/ego-lite](https://github.com/citrolabs/ego-lite), MIT skill + free macOS-only Chromium app) is driven not through MCP tool calls but through `ego-browser nodejs <<'EOF' … EOF` Bash heredocs, where navigation/observation/action/output helpers are pre-injected into one Node script — so a multi-step interaction costs one tool round-trip instead of one per action, and each agent works inside an isolated **Task Space** that inherits the user's login state without competing for the user's tabs. That combination targets the two failure modes of the existing backends: Chrome MCP's per-session profile `SingletonLock` contention in multi-session setups (v5.18's unbundling note) and every framework's inability to get past SSO/2FA on internal test targets. Changes: `BROWSER_MODE` detection order becomes **`cmux` → `ego` → `chrome-mcp`** (`which ego-browser`; explicit intent via `/test-run ego`), the Step 1-A action map gains an ego column written against the *installed* `ego-browser` skill's real helper signatures, Step 5 requires `useOrCreateTaskSpace` at the top of every heredoc, Step 10 closes it with `completeTaskSpace(…, { keep: false })` (an un-closed space leaves orphaned renderer windows — a reported upstream issue), and Step 8's perf-trace fallback plus the Step 9 / `result-doc-skeleton.md` report enum cover the new mode. New `skills/test-run/references/browser-ego.md` carries the per-step procedures and three load-bearing guards: **login-state inheritance** (an inherited session can make a broken login flow read as `PASS`, and writes land in the real account — clear the session per-origin via `Storage.clearDataForOrigin`, never browser-wide, or record `SKIP`; production origins are off-limits for write-heavy scenarios), **blank `captureScreenshot()` on scrolled pages** (ego lite 0.4.5.5 — scroll to top first, never file a blank frame as evidence), and **handoff = hard stop** (`/test-run` is a machine gate feeding `ASTRA_TEST_RESULT`, so a "user is controlling" state records `SKIP` rather than calling `takeOverTaskSpace`). Deliberately *second*, not first: ego is macOS-only, has no headless/CI mode, and carries open rendering bugs, so `cmux` keeps priority and `chrome-mcp` remains the portable fallback and the only real performance-trace path. Nothing else in the plugin depends on ego, and it is never bundled (`plugin.json` unchanged). SemVer: minor (new capability, no behavior change for projects without ego installed).

The design encodes three external best practices on top of ASTRA house patterns: (1) **max iterations is the safety mechanism; the score is only a success signal** (Ralph-loop lesson) — so Stage 0.5 asks the max iteration count via `AskUserQuestion` on EVERY invocation, even when `--max-iter=N` is passed (the argument only pre-selects an option, it never skips the question); (2) **LLM-judge leniency bias** (scores cluster near the top of the scale) — mitigated by a triple exit gate (objective test-runner exit 0 ∧ score ≥ 90 ∧ P0 == 0), additive-from-0 scoring with mandatory file:line evidence per criterion, and a rubric frozen at Stage 0.3 (HITL-confirmed, immutable mid-loop; presets A–E live in `skills/loop/references/rubric-template.md`); (3) **fresh-context adversarial verification** — the read-only `loop-verifier` (sonnet, refute-first mandate) judges artifacts only, never the worker's rationale, and emits the machine-parseable `ASTRA_LOOP_RESULT: score=N verdict=PASS|FAIL p0=N iter=I` tail line (same contract style as `ASTRA_REVIEW_RESULT`; the PASS threshold ≥ 90 is deliberately stricter than the reviewers' ≥ 80 because this line terminates an autonomous loop). Loop exits: early exit on PASS, hard stop at max iterations, stall stop (2 consecutive non-improving scores → HITL continue/stop). A failing objective gate short-circuits the verifier for that iteration (saves a sub-agent run; the test failure list becomes the next iteration's fix directives). Reuses the autorun state-file protocol (`astra_state_*` with explicit scope `loop-{slug}`) and the ≤ 200-line iteration-summary handoff rule. `/loop` performs no commit/PR/merge — it converges the working tree and hands off to `/pr-merge` or manual git flow. New agent-naming class registered: `*-verifier` (adversarial loop-gate scoring, skill-invoked only).

> **v5.8 → v5.9 change**: `/pr-merge` now follows a two-phase policy.
