ASTRA METHODOLOGY · v5.18

원플로우 실행 가이드 — 설계부터 Merge까지 한 세션

v5.16+ 파이프라인은 블루프린트 작성 → 구현 → 테스트 → 적대적 검증 → PR 머지를 한 세션에서 연속 실행합니다. 중간에 cd도, 새 세션도 없습니다. 이 문서는 상황별 최적 진입 커맨드와 전체 흐름을 플로우차트로 정리합니다.

1어떤 커맨드로 시작할까? — 진입점 선택

답은 대부분 /blueprint <slug>입니다. 상황이 특수할 때만 다른 진입점을 씁니다.

일상적인 신규 기능
/service-planner → /blueprint

기획 후 blueprint 하나로 merge까지. 설계 결정과 머지 확인만 답하면 됩니다. 기본 권장.

아이디어 한 줄 → 완전 무인
/autorun "..." --max-iter=3

기획부터 머지까지 무인. 승격 대상과 진짜 블로커에서만 멈춥니다. 민감 로직에는 비권장.

설계를 사람이 검토한 뒤 진행
/blueprint --design-only

설계 커밋 후 정지(재개 체크포인트 기록). 검토 후 /sprint-init --resume으로 이어갑니다.

블루프린트가 이미 있음 / prompt-map 기반
/sprint-init <slug>

스캐폴딩 후 같은 파이프라인으로 연속 진행. --scaffold-stop이면 스캐폴딩만.

두 세션 병렬 스프린트
자동 승격 (또는 --isolated)

메인 워크트리 점유가 감지되면 두 번째 스프린트는 자동으로 worktree 격리로 승격됩니다.

파이프라인에 안 맞는 개방형 목표
/loop "..." --max-iter=5

"경고 0개로" 같은 수렴형 목표. 루브릭 동결 → 적대적 채점. 머지는 별도 /pr-merge.

2메인 플로우 — /blueprint <slug> 원플로우 전체

/sprint-init <slug>로 시작해도 ③부터 동일한 파이프라인입니다 (공유 SSoT: auto-pipeline.md).

3적대적 게이트 — 왜 테스트 PASS만으로는 안 되나

장치내용막는 실패
삼중 게이트테스트 PASS ∧ 점수 ≥ 90 ∧ P0 = 0 — 셋 모두 충족해야 merge 해금LLM 판정 점수의 관대함 편향 (점수 단독 통과 금지)
반박 우선 채점0점에서 시작, file:line 증거가 있어야만 가산. verifier는 작업자의 설명을 읽지 않음"완료했다" 자기 주장만 있고 실체 없는 구현
고정 루브릭SPRINT PRESET (부합 40 · 무결성 30 · 품질 30) — 반복 중 변경 불가기준을 움직여서 통과하는 편법
하드 캡 5회테스트 실패·verifier 실패가 하나의 반복 예산을 공유. 소진 시 merge 없이 리포트무한 루프 · 토큰 폭주 · 억지 merge
기계 판독 계약ASTRA_LOOP_RESULT: 꼬리 라인만 파싱. 라인 부재 = FAIL, 절대 PASS 아님산문("잘 된 것 같다")에서 통과를 유추하는 오판

4사람이 개입하는 지점 (모드별)

모드질문받는 것자동 처리
기본 (attended)
/blueprint · /sprint-init		 설계 결정 1~3개 · 최종 merge 확인 · 승격 대상(dev/staging/skip) · Critical 리뷰 이슈 잔존 시 격리 모드 · 테스트/검증 반복 · 수정 적용 · 커밋/푸시/PR
무인 (--auto)
/autorun · /sprint-init --auto		 시작 시 최대 반복 수(autorun) · 승격 대상은 --auto여도 항상 질문 · 진짜 블로커(gh 인증·충돌·Critical) merge 확인 포함 나머지 전부
정지 옵션 --design-only(blueprint: 설계 커밋 후 정지) · --scaffold-stop(sprint-init: 스캐폴딩만) · /sprint-init --resume(크래시/정지 후 재개)
